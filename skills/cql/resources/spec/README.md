# CQL Specification — Local Verbatim Copy, by Version

The CQL specification, one file per section, for each version that engines actually implement.
Use this instead of fetching cql.hl7.org: web fetches truncate long pages and paraphrase the text.

Build it with `bash scripts/fetch-spec.sh` from the skill folder. Everything in this directory
except this README is generated by that script from pinned commits. None of it is distributed with
the skill, because the spec text is HL7 content. If `1.5.3/INDEX.md` is missing, run the script
before searching.

**Use only `cql-tests/` for conformance tests, whatever version the engine targets.** The test
suites published with the spec (the `tests.zip` on each version's tests page, and `tests/` in
HL7/cql) are out of date, and in places they contradict the spec text and each other. The current
tests are maintained in cqframework/cql-tests. The build doesn't copy the published suites, so don't
cite them, fetch them, or treat them as evidence.

## Which version applies

Most engines implement **1.5** or **1.4**, not 2.0. Answer a semantics question against the version
the engine targets, then check whether later text changed it.

1. **Find the target version.** For the cqframework reference translator (the one behind the CQL
   language server and the cqf engine), `CqlCompilerOptions.compatibilityLevel` defaults to `"1.5"`
   (`cql-to-elm/src/commonMain/kotlin/org/cqframework/cql/cql2elm/CqlCompilerOptions.kt:35`, at
   5.4.0). A library or project can override it. For other engines, check their documentation;
   don't assume.
2. **Quote that version's text.** For 1.5 targets that is `1.5.3/`. For 1.4 targets it is `1.4/`.
3. **Check the change lists.** `CHANGES-1.4-to-1.5.3.md` and `CHANGES-1.5.3-to-2.0.0.md` list every
   section whose wording changed. If the section you are quoting appears in one, quote the other
   version's text as well.
4. **Treat 2.0.0 text as a clarification, not as the rule for older targets.** 2.0.0 is trial-use.
   Where it adds a rule that 1.5.3 does not state, the accurate finding for a 1.5 engine is "1.5.3 is
   silent; 2.0.0 clarifies X". Example: the `null is Integer` → `false` note (HL7 Jira FHIR-55657)
   exists only in 2.0.0. The 1.4 and 1.5.3 `Is` entries say nothing about null.

## Layout

Each version folder contains:

- `INDEX.md`: every section, its heading path, its file, and its URL on cql.hl7.org.
- `sections/<page>/<NNN>-<anchor>.md`: one section per heading. The header comment records the
  version, the heading path, the URL with its anchor, and the source line range. Inline markup is
  stripped (markdown `<span>`s, AsciiDoc `[.kw]#…#` roles), so the text matches the rendered site
  and can be quoted directly. The 1.4 files keep AsciiDoc block syntax (`----`, `*bold*`).
- `pages/*.md` or `pages/*.adoc`: the raw page sources, unmodified.
- `elm/*.xsd`: the ELM schema for that version.

Section paths are heading titles without the page title and without section numbers, so a section
has the same path in every version, for example `Type Operators > Is`.

`CHANGES-<old>-to-<new>.md` compares consecutive versions section by section. It ignores
source-format markup, since 1.4 is AsciiDoc and later versions are markdown, so it reports changes
in wording. Its diffs show the normalized text: quote from the section files, never from a diff.

## Pages worth knowing

| Page | What it settles |
| --- | --- |
| `09-b-cqlreference` | Each operator's signature, null behavior, and examples. Start here for "what does X return". |
| `03-developersguide` | Types: type testing, casting, choice types, conversion precedence, implicit conversions, tuples, list and union typing. |
| `05-languagesemantics` | Formal semantics: queries, nulls, the type system. |
| `06-translationsemantics` | How CQL maps to ELM: what the translator is supposed to emit. |
| `04-logicalspecification` | ELM operator semantics, including `As`, `Is`, the `strict` flag, and interval null bounds. |
| `15-h-timeintervalcalculations` | Duration and difference calculations, with worked tables. |
| `02-authorsguide` | Informal explanations. Useful, but defer to the pages above when they disagree. |

## How to look things up

```sh
SPEC=resources/spec   # relative to the skill folder

# Find a section by heading, in every version
grep -i '\[Type Operators > Is\]' $SPEC/*/INDEX.md

# Find every passage that mentions a phrase, per version
grep -ril 'run-time type' $SPEC/1.5.3/sections

# Did a section change between versions?
grep -i '\[Type Operators > Is\]' $SPEC/CHANGES-*.md

# Conformance-test examples for an operator (the current cql-tests suite)
grep -n -i -A4 '<expression>[^<]*\bis\b' $SPEC/cql-tests/CqlTypeOperatorsTest.xml
```

## Citing the spec

Every claim about what CQL means needs a citation in this form:

> CQL 1.5.3, [Type Operators > Is](https://cql.hl7.org/N1A/09-b-cqlreference.html#is): "…exact
> quote…"

- **Quote the text; don't paraphrase it.** Copy it from the section file.
- **Name the version,** and make it the version the engine targets. If the section changed in
  another version, say what that version says too.
- **"The spec is silent" is a valid finding.** Say so explicitly, and name the sections and
  versions you searched. Never fill a gap with reasoning and present it as the spec.
- **Conformance tests are informative, not normative.** Every version's
  [tests page](https://cql.hl7.org/N1A/tests.html) says: "The tests defined here are informative,
  not normative aspects of the specification. If there is a discrepancy between the behavior of a
  test and the specification, the specification should be considered the source of truth." Use a
  matching `<test>` from `cql-tests/` as executable evidence that is easy to check, and cite it as
  `[src: CQL-TESTS <file>.xml <TestName>]`. Where a test and the prose disagree, report the
  disagreement and treat the spec text as authoritative. A test's absence is worth noting: no test
  covers the case.
- **Never use the tests published with the spec.** They are out of date (see
  [Versions](#versions)).

## Running the conformance tests

[cqframework/cql-tests-runner](https://github.com/cqframework/cql-tests-runner) runs the cql-tests
suite against any engine exposed through a FHIR server's
[`$cql` operation](https://hl7.org/fhir/uv/cql/OperationDefinition-cql-cql.html). The tests use no
data (they have no retrieves), so `$cql` is the only capability the server needs. Use the runner to
find out what an engine *does* on a case. A result is evidence of behaviour, not of what the spec
requires, and it needs the engine and translator versions recorded with it.

- **Configure:** copy `conf/localhost.json` and set `FhirServer.BaseUrl`, the translator and
  engine names and versions under `Build`, and optionally `Tests.SkipList` or `Tests.OnlyList`
  (entries name `testsName`, `groupName` and `testName`) to run a subset.
- **Run with Docker:**

  ```sh
  docker run --rm --network host -v $(pwd)/conf:/app/conf -v $(pwd)/results:/app/results \
    hlseven/quality-cql-tests-runner:latest run-tests conf/<your-config>.json ./results
  ```

- **Or run from source** (Node 25): `npm install`, `git submodule update --init --recursive`, then
  `npx tsx src/bin/cql-tests.ts run-tests conf/<your-config>.json ./results`.
- **Results** are written as JSON to the results folder. Results for several engines are posted in
  [cqframework/cql-tests-results](https://github.com/cqframework/cql-tests-results). A hosted
  runner is at <https://cql-tests-runner.quality.hl7.org>.
- The runner brings in cql-tests as a git submodule, which can be at a different commit from the
  copy in `cql-tests/` (see `cql-tests/REF`). Check which commit it is before comparing a run's
  results with a test cited here.

The runner's README is the authority on its options; check it before relying on the details above.
- **Engine and translator source are not the spec.** They show what an implementation *does*.
  A merged fix shows what its maintainers decided. Neither shows what the spec *requires*.

## Known caveats

- One explicit anchor in the 1.5.3 and 2.0.0 sources, `04-logicalspecification.html#not-equal-5`,
  does not exist on the rendered sites. Every other checked anchor resolves (653 in 1.4, 690 in
  1.5.3, 752 in 2.0.0, checked 2026-10-22).
- The duration appendix (`15-h-timeintervalcalculations`) marks some worked-formula lines as
  headings in its source (for example `# (2013 - 2012) * 12 + (6 - 3) = …` in 1.5.3), so its
  INDEX.md has section entries named after formulas. The splitter follows the source so anchors
  match the published site. Cite the appendix's Definition sections.
- On the 1.4 site, repeated headings without an explicit anchor get `-2`, `-3`, … ids; on the 1.5
  and later sites they get `-1`, `-2`, …. The splitter follows each.
