# FHIR Shorthand (FSH)

FSH is a text language for defining FHIR artifacts. SUSHI compiles it into FHIR JSON: one
StructureDefinition, ValueSet, CodeSystem or instance per item. This skill covers FSH 3.0.0, the
current release, as implemented by SUSHI 3.x, for FHIR R4 projects.

## Workflow

1. Write the FSH. Give every profile, extension, value set and code system an explicit `Id`
   (lowercase, hyphenated). Without one, SUSHI uses the item name as the id, and the name also
   ends up in the canonical URL. Instances take no `Id` keyword: the instance name is its id, so
   write `Instance: example-bp`, or set `* id = "example-bp"` as a rule.
2. Compile with `sushi build .` (see [sushi-project.md](resources/sushi-project.md)). For a quick
   check outside an IG, use a `sushi-config.yaml` with only `canonical`, `fhirVersion: 4.0.1` and
   `FSHOnly: true`.
3. Fix every error. SUSHI skips each rule that fails and still writes the rest, so a build with
   errors produces output that looks complete but is missing constraints.
4. Check the JSON in `fsh-generated/resources/` when the intent matters. A profile's
   `differential` shows exactly what each rule produced.

If you can't run SUSHI, say so, and check the FSH against the spec sections instead.

## Rules that are easy to get wrong

Each of these is in the spec. The SUSHI errors quoted are from SUSHI 3.21.0.

- **`=` in a profile is a pattern.** `* code = $LNC#85354-9` sets `patternCodeableConcept`, so
  other codings may appear alongside it. Add `(exactly)` only when you need `fixed[x]`, which
  forbids anything extra. In an instance, `=` just sets the value, and `(exactly)` has no meaning.
- **Extensions in profiles need `named`.** Write
  `* extension contains ReviewedBy named reviewedBy 0..1 MS`. Without `named`, FSH reads
  `ReviewedBy` as an inline extension, which profiles can't have ("Inline extensions should only be
  defined in Extensions"). In an instance, set it through the local name:
  `* extension[reviewedBy].valueReference = Reference(Practitioner/example)`.
- **Inline extensions are for complex extensions.** In an `Extension` item,
  `* extension contains code 1..1 and period 0..1` defines sub-extensions. Constrain each with
  `* extension[code].value[x] only CodeableConcept`. SUSHI then sets the parent's `value[x]` to
  `0..0`, and likewise sets `extension` to `0..0` on an extension that only constrains `value[x]`.
- **Slicing goes in three steps, in order.** First the slicing logic with caret rules
  (`* component ^slicing.discriminator.type = #pattern`, `...discriminator.path = "code"`,
  `* component ^slicing.rules = #open`). Then `* component contains systolic 1..1 and diastolic
  1..1`. Then constrain each slice, such as `* component[systolic].code = $LNC#8480-6`. Without
  step 1, SUSHI fails with "No slicing found". Extension arrays are the exception, because FHIR
  already slices them by `url`.
- **Multiple reference targets go inside one `Reference()`.** Write
  `* subject only Reference(Patient or Group)`, not `Reference(Patient) or Reference(Group)`.
- **Choice elements are narrowed, then addressed by type.** Write `* value[x] only Quantity`, then
  use `valueQuantity` in later paths and instances. A simple extension's value is `value[x]`:
  `* value[x] only Reference(Practitioner)`.
- **`^` sets metadata, not data.** `* ^status = #active` sets `StructureDefinition.status`.
  `* code ^short = "..."` sets the element's `short`. Without `^`, the rule constrains instance
  data.
- **Codes and quantities have their own syntax.** A code is `system|version#code "display"`, with
  the version and display optional, for example `$SCT#38341003 "Hypertension"`. A UCUM quantity
  is `120 'mm[Hg]'`.
- **Soft indexing fills arrays without numbers.** `[+]` moves to the next item and `[=]` stays on
  the current one: `* name[+].given[+] = "Ana"` then `* name[=].family = "Silva"`.
- **Escape rule set arguments.** Inside `insert MyRuleSet(a, b)`, escape a literal comma or
  closing parenthesis as `\,` or `\)`, or wrap the whole argument in `[[ ]]`. Don't escape an
  opening parenthesis: SUSHI 3.21.0 then misreads the argument.
- **Instances default to `Usage: #example`.** Use `#definition` for conformance resources the IG
  publishes, such as a SearchParameter or Questionnaire, and `#inline` for resources that exist
  only inside another one (a contained resource or a Bundle entry).
- **Give extensions a `Context:`.** It is trial use in FSH 3.0.0 but RECOMMENDED over caret rules
  on `^context`. `Context: Observation, Condition.code` gives `element` contexts, a quoted
  string such as `Context: "(Condition | Observation).code"` gives a `fhirpath` context, and an
  extension's name, id or URL gives an `extension` context.
